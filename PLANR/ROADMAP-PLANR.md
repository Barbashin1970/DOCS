## Drill-down аналитика (Пространство → Группа → Проект)  ⬜ — СЛЕДУЮЩИЙ

Дать агенту извлекать данные по уровням иерархии EPS: весь портфель → группа проектов
(facility) → конкретный стройобъект. Принцип ZET: **скоуп задаётся детерминированно** (каскадные
селекторы в UI, не «угадывание» из текста) → грунтинг заземляется РОВНО на выбранное подмножество.

- [ ] **Данные (group-plumbing):** puller кладёт `group_id/group_name` в каждый этап и проект
      (project.parentId → узел facility = группа) + **per-group агрегаты** (иначе фильтр по
      усечённому top-50 врёт, как в фиксе счётчиков). Айбим: «Западный филиал» / «Восточный (тест)».
- [ ] **Агент:** `planr_ask(space_id, question, scope={group|project})` → `_build_planr_context`
      фильтрует срезы + берёт per-group/‑project агрегаты; в грунтинг — строка «СКОП: <уровень> <имя>».
- [ ] **UI:** каскад над инпутом Студии: Пространство → Группа → Проект (из снапшота); скоуп
      уходит в planr-ask. Уровень «Проект» доступен уже сейчас (project_name в этапах есть),
      уровень «Группа» — после group-plumbing.
- [ ] **Проверка:** «покажи риски по Западному филиалу», затем «по объекту Гостиница» — числа
      совпадают с ручной суммой по подмножеству (детерминированно).
