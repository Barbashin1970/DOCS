> каталог. Здесь только Plan-R; смежные темы — в корне `docs/` (СИГМА, ZET, АРХИ).

## Идея интеграции

**Plan-R — пассивная витрина, РАГРАФ — активный слой управления.**

Plan-R отвечает на вопрос «**что происходит**»: графики, WBS-этапы, просрочки,
дашборды. Но сам ничего не предпринимает — руководитель должен смотреть, замечать
и реагировать вручную. РАГРАФ — надстройка «системы **действия**» над этой витриной,
отвечающая на вопрос «**что делать**». Контур: ETL тянет данные Plan-R через
публичный API → детерминированные регламенты и агент считают риск → запускается
действие (уведомление ответственному, задача, эскалация).

Ключевой принцип — **детерминированный верификатор с асимметрией информации** (ZET):
все числа считает КОД по данным Plan-R, LLM только формулирует. Отсюда нет
галлюцинаций цифр по построению — картину рисков нельзя «придумать».

### Два режима работы

| Режим | Кто инициирует | Что делает РАГРАФ | Где в продукте |
|---|---|---|---|
| **Реактивный** — диалоговый агент | руководитель СПРАШИВАЕТ | отвечает по данным портфеля; **drill-down**: Пространство → Группа проектов → Объект; банк из 16 вопросов (сроки, критпуть, бюджет, подрядчики, свежесть графиков) | Студия аналитика (`/sandbox`, режим Plan-R) |
| **Проактивный** — регламенты-детекторы | система САМА | на каждом pull прогоняет регламенты, находит риск и **сама** шлёт адресный вердикт ответственному ДО штрафа/простоя | Стройпортфель (`/planr`), авто-пуш в мессенджер |

**No-code расширяемость.** Проактивные сценарии — это регламенты в визуальном
редакторе Flow DSL (5 узлов: датчик→вход→формула→развилка→выход). Новый
востребованный сценарий контроля добавляется без программирования: методолог
рисует регламент поверх данных Plan-R, и он начинает фаерить на каждом pull.
