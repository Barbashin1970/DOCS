# ТЗ команде Plan-R: данные и эндпойнты для РАГРАФ

**Дата:** 2026-07-04. **Адресат:** команда разработки Plan-R (bim-info / НГУ).
**От:** команда РАГРАФ. **Цель:** перечень данных/эндпойнтов, которых не хватает в
публичном API Plan-R, чтобы РАГРАФ включил проактивные функции (ресурсы, разрешения,
план-факт, адресные уведомления). Каждый пункт: **что нужно · зачем (какая функция) · формат**.

**Контекст.** РАГРАФ — надстройка «системы действия» над Plan-R: тянет графики/этапы/просрочки
через 6 GET-эндпойнтов, применяет детерминированные регламенты и доставляет вердикты ответственным.
Сейчас упираемся в отсутствие ряда данных в API (детали — [REQ-PLANR-INTEGRATION-EXPANSION.md](REQ-PLANR-INTEGRATION-EXPANSION.md) §7).

## P1 — разблокирует ключевые функции

### 1. Ресурсы (люди и техника): план/факт по этапу ⭐ (разблокирует Q4/Q5)
- **Что:** эндпойнт `/resources` (или поле в `/wbs`): по каждому WBS-этапу — плановая и
  фактическая численность/состав ресурсов: **люди** (по специальностям/бригадам/субподряду) и
  **техника** (единицы, тип). Плюс **справочник имён** для ресурсных UUID (сейчас атрибуты
  исполнителя `…017/…018` = сырой Guid без расшифровки).
- **Зачем:** вопросы диалогового аналитика «обеспеченность людьми план/факт» и «обеспеченность
  техникой план/факт» (Q4/Q5) сейчас БЛОКИРОВАНЫ — в API нет ресурсного планирования. С этими
  данными РАГРАФ считает дефицит ресурса → регламент «риск простоя из-за нехватки бригад/техники».
- **Формат:** `GET /resources?EpsId=<version>` → `[{wbsId, kind: person|equipment, role, plan, fact}]`;
  либо `resourcePlan/resourceFact` в values WBS + `GET /resource-dictionary` (uuid → название).

### 2. Пользователи с ролями и контактами (`/users`) ⭐ (адресная доставка)
- **Что:** `GET /users` → сотрудники пространства с ФИО, **email**, ролью, и (если есть) telegram/max id.
- **Зачем:** РАГРАФ доставляет вердикт КОНКРЕТНОМУ ответственному (Куратор/ГИП/PM объекта). Сейчас
  API отдаёт только ФИО в EPS-атрибутах, без контактов → приходится вести свой справочник вручную.
  С `/users` — сквозная адресная маршрутизация уведомлений о рисках.
- **Формат:** `[{id, fullName, email, role, phone?, messengerIds?}]`.

### 3. Читаемые булевы вехи разрешений/ГГЭ (подтвердить наличие) ⭐ (gate-регламенты)
- **Что:** гарантировать, что атрибуты **разрешение на строительство**, **разрешение на ввод**,
  **ГлавГосЭкспертиза (ГГЭ)** заполняются и отдаются через `/eps-attribute-values` (bool + дата).
- **Зачем:** регламенты-gate «нельзя строить/сдавать без разрешения» (юридически весомо, ст. 9.5
  КоАП). У РАГРАФ логика готова — нужны заполненные поля на боевых объектах.
- **Формат:** bool + опц. дата выдачи/окончания в существующих `/eps-attribute-values`.

### 4. Стабильный доступ к target-версиям (план-факт / EVM)
- **Что:** target-версии графика доступны и матчатся с actual по `code`/`materialPath` (сейчас они
  есть в `/versions` status=target, но РАГРАФ их пока не тянет из-за объёма).
- **Зачем:** собственный детерминированный расчёт SPI/CPI/BAC от базового плана (флагман
  «детерминированный верификатор») вместо пересказа движкового slip.
- **Формат:** как есть; желательно лёгкий `GET /wbs?EpsId=<target>&fields=code,cost,finish` (усечённый).

## P2 — повышает качество и снимает костыли

### 5. `updatedAt` на узлах schedule/version (свежесть графика)
- **Что:** сейчас на узлах schedule/version поле `updatedAt` = null (только `createdAt`); дату
  последнего ПЕРЕСЧЁТА берём как MAX(`updatedAt`) по WBS — костыль.
- **Зачем:** индикатор «график давно не рассчитывали» (искажает картину просрочек) — считали бы
  напрямую по версии, без обхода всех WBS.

### 6. Эндпойнт импорта расписания / запись дат этапа (Гант для демо)
- **Что:** дать API-способ загрузить расписание (или писать start/finish этапа). Сейчас даты/slip/
  criticalPath — только движок (PUT возвращает 200, но GET=null).
- **Зачем:** API-созданные (демо/what-if) проекты показывают ПУСТОЙ Гант — нельзя наполнить график
  без ручного импорта в UI. Импорт-эндпойнт закрыл бы это.

### 7. Прочие точечные
- `GET /wbs-relations` (сейчас 405) — дерево зависимостей → корректный критпуть/каскад.
- **tenant-scoping** для `/eps-attribute-values` (сейчас не скоупится — джойним по epsId вручную).
- Явное поле **«Сумма договора»** (сейчас прокси из cost_plan WBS).
- Единый `updatedAt`/`recalculatedAt` версии = время последнего планирования.

## Что РАГРАФ уже умеет с текущим API (для контекста)
Читает: EPS-дерево (space/facility/project/schedule/version/wbs), атрибуты договора, WBS
(progress, cost, criticalPath, slip, finish на боевых), свежесть по WBS.updatedAt. Пишет: создание
узлов (`POST /eps`), атрибутов (`PUT /eps-attribute-values`), WBS (`POST /wbs`, EpsId в теле),
статус версии (`PUT /versions/{id}` — `actual`). **НЕ** пишет: даты/slip/criticalPath этапа (движок).

## Приоритет для нас
**1 → 2 → 3** дают максимум пользы: ресурсы (новые функции Q4/Q5), контакты (адресные пуши рисков),
разрешения (gate-регламенты). Готовы созвониться и согласовать форматы.
