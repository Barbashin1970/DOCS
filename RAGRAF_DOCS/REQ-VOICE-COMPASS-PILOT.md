# REQ: «Сима» — голосовой компас по регламентам (пилот: городская среда + строительство)

> Оператор/руководитель **спрашивает голосом** → система отвечает, **опираясь на корпус
> регламентов** (RAG-компас), с цитатой на регламент и пункт норматива, при необходимости
> прогоняя нужный регламент на живых данных. Нейросеть ведут **жёсткие потоковые схемы**
> регламентов; человек подтверждает любое действие.
>
> Опора на уже существующее в РАГРАФ (не изобретаем): семантический поиск
> [`embedding_index.py`](../backend/app/services/embedding_index.py), RAG-чат
> [`/sandbox/chat`](../backend/app/api/sandbox.py), триплеты + SPARQL
> [`/knowledge/sparql`](../backend/app/api/knowledge.py), исполнитель `flow_executor`, PROV-O.
> STT **заимствован** из `~/NSK_OpenData_Bot` (Web Speech API). Дата: 2026-06-10.

> **Статус (2026-06-10): испытания начались.** Связка работает end-to-end в Студии аналитика:
> голосовой/текстовый вопрос → гибридный поиск по корпусу → ответ с цитатой на регламент и пункт
> норматива. Ранние прогоны подтвердили ключевые свойства: **нормативная цитата** (напр. ГК РФ
> ст. 708/330 по просрочке этапа), **анти-галлюцинация** (вопрос вне корпуса → честное «такого
> регламента нет, источник отсутствует» — 0 выдуманных правил), **живой прогон** («нет live-данных —
> можно прогнать на тесте»), **создание черновика из текста** («собери регламент: …»). Облачный LLM
> и Web Speech STT рабочие; транзиентный 429 смягчён ретраями. Формальный замер acceptance
> (§6, ≥ 12/15) — следующий шаг оператора.

## 1. Зачем и для кого

ЛПР (диспетчер ЕДДС, дежурный ЦОДД, прораб, руководитель) не открывает редактор и не пишет
SPARQL — он **спрашивает словами**: «какой регламент по ночному шуму у школы и что сейчас по
датчику?», «что делать при превышении PM2.5 в час пик?», «есть ли регламент по входному контролю
материалов и какой порог расхождения?». Система должна ответить **по регламентам**, а не из общих
знаний LLM, и показать, **откуда** (регламент + пункт норматива). Это «ИИ-модератор», а не
«автономный агент»: он находит, объясняет, считает — но действие (наряд) подтверждает человек.

**Имя ассистента — «Сима»** (созвучно «Сигма»; единое имя для всей системы). Оператор обращается
«**Сима, …**» — это же слово служит wake-word'ом и срезается из распознанного текста (алиас
«Сигма» оставляем — на слух их легко спутать).

**Пилотные домены** (у обоих уже есть регламенты и граф знаний):
- **Городская среда** (`nsk_city`): экология (`nsk-ecology`, `nsk-nmu-smog-trap`, `nsk-mobile-index`),
  дорожное движение (`nsk-traffic-forecast`, `nsk-traffic-signal`), парковка (`nsk-parking-*`).
- **Строительство** (`construction`): `construction-ppe-violation` (СИЗ/каски),
  `construction-overdue-stage` (сроки), `construction-material-acceptance` (входной контроль),
  `construction-portfolio-risk`, `construction-fiber-cable-protection`.

## 2. Заимствованный STT (из NSK_OpenData_Bot)

Голос → текст там сделан **браузерным Web Speech API** — ноль бэкенда, ноль инфраструктуры
(в Chrome/Edge распознаёт сам браузер). Лифтуем паттерн один-в-один в Студию аналитика РАГРАФ
(поле чата `/sandbox`), добавив кнопку 🎙 рядом с вводом запроса:

```js
// Заимствовано из ~/NSK_OpenData_Bot/src/static/index.html (Voice Input, Web Speech API)
let _rec = null;
function toggleVoice() {
  const SR = window.SpeechRecognition || window.webkitSpeechRecognition;
  if (!SR) { alert('Голосовой ввод работает в Chrome и Edge.'); return; }
  if (_rec) { _rec.stop(); return; }
  _rec = new SR();
  _rec.lang = 'ru-RU';
  _rec.continuous = false;
  _rec.interimResults = false;
  _rec.onresult = (e) => {
    let text = e.results[0][0].transcript;
    // срезаем wake-word «Сима» — имя ассистента, созвучно «Сигма» (алиасы: Сигма/sigma/sima)
    text = text.replace(/^(?:с[ие]г?м[ао]|si(?:gm?a|ma))[!,.:)?\s]*/i, '').trim();
    setChatInput(text);
    resetMic();
    if (text) sendChat();      // сразу уходит в /sandbox/chat
  };
  _rec.onerror = resetMic;
  _rec.onend = resetMic;
  _rec.start();
}
```

**Что это даёт сразу:** голос работает уже сегодня, без сервера. **Ограничения честно:** Chrome/Edge,
только онлайн, требует HTTPS. Для офлайна/прода (киоск диспетчера, не-Chrome) — фоллбэк на серверный
Whisper-эндпоинт `POST /api/voice/transcribe` (этап 4, опционально).

## 3. Архитектура пилота — гибридный нейро-символьный компас

Поток одного голосового запроса:

```
голос ──STT──▶ текст запроса
   │
   ├─ 1. СИМВОЛЬНОЕ СУЖЕНИЕ (триплеты/SPARQL): фасет по домену/классу датчика/действию
   │      → набор кандидатов-регламентов (из 100 → десяток релевантных)
   │
   ├─ 2. ВЕКТОРНЫЙ РАНК (эмбеддинги bge-m3): среди кандидатов — концептуально близкие
   │      (embedding_index.search) → top-k регламентов
   │
   ├─ 3. (опц.) ПРОГОН: flow_executor гоняет найденный регламент на ТЕКУЩИХ данных
   │      → уровень + рекомендация + трасса (живое заземление, не только текст)
   │
   ├─ 4. ОРАКУЛ С КОНТРАКТОМ (LLM): собирает ответ ТОЛЬКО из retrieved-регламентов
   │      (+ результат прогона), с цитатой regulation_id и пункта норматива (PROV-O)
   │
   └─ 5. ВЕРИФИКАЦИЯ + ЧЕЛОВЕК: ответ сверяется с корпусом/SHACL; если из ответа следует
          ДЕЙСТВИЕ (наряд) — подтверждает оператор. LLM не действует и не выдумывает правил.
```

Это «семантика + контур»: вектора дают близость (ловят «наводнение»≈«протечка», чего regex не
может), а контур регламента (граф + критерий + пункт норматива) даёт **заземление и
проверяемость**.

## 5. Этапы

> **Статус (2026-06-10):** P1 ✅ (голос «Сима» в Студии) · P2 ✅ (обогащённый индекс + гибридный фасет `domain`) · P3 ✅ (живой вердикт по явному запросу) · разрыв №1 (нормативная цитата) ✅. Дальше — P4 (оценка 15 вопросов §6 + опц. Whisper-фоллбэк).

1. **P1 — Голос в Студию (дни).** Вшить заимствованный STT (кнопка 🎙) в чат `/sandbox`. Уже
   сегодня: голосовой вопрос → текущий RAG-ответ с цитатами на регламенты пилотных доменов.
   *Артефакт:* рабочий голосовой чат на Chrome/Edge.
2. **P2 — Обогатить компас (1–2 недели).** Расширить `_doc_text` в `embedding_index` (добавить
   событие-триггер, классы датчиков, текст пункта норматива, действия выходов, критерий) +
   **гибрид**: SPARQL-фасет по домену/датчику ⨉ эмбеддинги. Точность на 100 регламентах по 2
   доменам.
3. **P3 — Ответ, который исполняет (1–2 недели).** Чат не только цитирует найденный регламент, но
   и прогоняет его `flow_executor` на текущих данных (для nsk_city — live ETL) и вставляет вердикт
   («по регламенту X, при PM2.5=80 — уровень 2, рекомендация Z»).
4. **P4 — Оценка + демо + (опц.) Whisper-фоллбэк.** Набор из ~15 типовых голосовых вопросов по 2
   доменам, метрика «ответ опёрся на правильный регламент с цитатой» (см. §6); демо-сценарий;
   серверный Whisper-эндпоинт для не-Chrome/офлайна — по необходимости.

## 6. Критерий «пилот удался» (acceptance)

- Набор **15 голосовых вопросов** (по 7–8 на домен, см. §7). Успех вопроса = ответ (а) опирается на
  **правильный** регламент, (б) содержит **цитату** на regulation_id + пункт норматива, (в) **не
  выдумывает** правил, которых нет в корпусе.
- Порог пилота: **≥ 12 из 15** успешны; **0** «галлюцинированных» правил (это жёсткий ноль —
  оракул отвечает только из retrieved).
- Бонус (P3): для ≥ 5 вопросов ответ содержит **живой вердикт** прогона регламента.

## 7. Примеры голосовых вопросов (для оценки)

> Оператор начинает с обращения «**Сима, …**» — wake-word срезается, дальше идёт сам вопрос.

**Городская среда:**
- «Какой регламент по ночному шуму у школы и что сейчас по датчику?»
- «Что делать при превышении PM2.5 в час пик?»
- «Есть ли регламент по смогу при безветрии?»
- «Какая загрузка парковки ВКИ и когда переполнение?»
- «Какой прогноз по пробкам на завтра и какой регламент его считает?»

**Строительство:**
- «Какой порог расхождения по накладной для блокировки оплаты?»
- «Что делает регламент по каскам и когда эскалация ОТ-инженеру?»
- «Какой регламент по срокам этапа и когда штраф подрядчику?»
- «Есть ли регламент по защите оптоволокна от копки?»
- «Как считается портфельный риск стройпроектов?»

## 8. Честные границы

- Web Speech API — Chrome/Edge, онлайн, HTTPS; для прод-киоска/офлайна нужен Whisper (P4, опц.).
- Оракул-**узел** внутри потока (LLM как типизированный предикат в графе) — **не** этот пилот, а
  роадмап (см. учебник Часть 5 / OTCHET-NIR §6.11). Здесь LLM заземляется на стороне чата.
- LLM строго как оракул-с-контрактом: retrieve → verify → cite, с логом вызовов в audit (PROV-O).
  Никакого free-form и никакого автодействия без человека.
