# REQ: PUSH-приём ШУМ-ИИ — сейсмоакустика и шумовое загрязнение

> Источник сигналов для домена **ШУМ-ИИ** (подсистема системы ГОРОД-ОМ-ИИ — внешний Оракул для
> ЦД СУ, НИР-2024 §2.4). Внешняя система ПУШит нам JSON шумовых/сейсмических событий.
> Сделано по образцу PUSH-приёмника видеодетектора парковки (vd-anpr, см.
> [INTEGRATION-ANPR-PUSH.md](INTEGRATION-ANPR-PUSH.md), [REQ-PUSH-ANPR-PARKING.md](REQ-PUSH-ANPR-PARKING.md)).
> Дата: 2026-06-10.

## 1. Контракт приёма (этап 1 — СДЕЛАНО)

**Эндпоинт:** `POST /api/ingest/noise` — JSON в теле запроса. Опциональный заголовок
`X-Ingest-Token` (тот же shared-token, что у ANPR; если `INGEST_TOKEN` пуст — приём открыт).

**Тело — три формы (на выбор интегратора):** JSON-массив событий, конверт `{"events":[…]}`,
одиночный объект. Лимит пачки — `MAX_BATCH = 5000` (иначе `413`; агрегируйте на месте).

**Два формата события** (оба ложатся в одну таблицу, поле `kind`):

```jsonc
// сырой 3-осевой сэмпл сейсмоакустики (kind='sample')
{ "sensor_id": "shum-vki-01", "x": 8736, "y": 2342, "z": 0,
  "ts": 1728961597128, "pos": "44.34532N 72.4534543E" }

// высокоуровневое событие — превышение/классификация (kind='event')
{ "sensor_id": "shum-vki-01", "event_type": "train", "level_db": 78.4,
  "ts": 1728961597344, "coords": "44.34532N 72.4534543E" }
```

Поля (все опциональны, неизвестные сохраняются в `raw_payload`):

| Поле | Тип | Смысл |
|---|---|---|
| `ts` (или `timestamp`) | int/str | время события, **epoch миллисекунды** |
| `sensor_id` (или `id`) | str | уникальный ID датчика (геопривязка по ID, НИР-2024 §2.4) |
| `x`, `y`, `z` | float | амплитуда сейсмосигнала по 3 осям (1 датчик = 3 разнонаправленных) |
| `level_db` (или `laeq`) | float | уровень шума LAeq, дБ (шумовое загрязнение) |
| `event_type` (или `vehicle_type`) | str | тип источника/события: `train`, `threshold_exceed`, … |
| `pos` / `coords` | str | координаты строкой `"44.34N 72.45E"` (разбираются в `lat`/`lon`, сырое — в `pos`) |
| `lat`, `lon` | float | если датчик уже разобрал координаты |
| `confidence` | float | уверенность классификации 0..1 |

**Идемпотентность:** `event_id = sha1(sensor_id | ts_ms | сигнатура показаний)` — повторная
присылка того же события гасится PRIMARY KEY (поле `duplicates` в ответе — штатное).

**Ответ:** `{ok, received, inserted, duplicates, skipped}` (`skipped` — события из будущего > сутки).

**Где в коде:**
- эндпоинты — [`backend/app/api/noise.py`](../backend/app/api/noise.py);
- хранение/идемпотентность — `backend/app/services/live_data_store.py`
  (`append_noise_events`, таблица `noise_events` в `live_etl.duckdb`, тот же RLock/WAL, что у ANPR);
- роутер зарегистрирован в `backend/app/main.py` (`tags=["noise"]`).

**Read-эндпоинты (для проверки и табло):**
`GET /api/ingest/noise/recent` · `…/stats` · `…/health` (светофор живости потока по `received_at`).
`DELETE /api/ingest/noise` — сброс демо/тестовых данных.

## 2. План развития (этап 2+ — В ОЧЕРЕДИ)

Приёмка работает; дальше — превратить поток в реакции (как у ANPR/DAS):

1. **Подтип датчика в Библиотеке датчиков** (`sensor_schema_store`): класс `noise` → подтип
   `shum-ii-seismoacoustic` (поля `x/y/z/level_db/event_type/pos`) и `shum-ii-pollution`
   (`level_db`), чтобы поток можно было привязать к входам регламента (`bindsTo`).
2. **Severity-эвристика и агрегаты** (по образцу `fiber_stats`): порог по `level_db` (норма/
   внимание/превышение), всплески сейсмики, разбивка по `event_type`.
3. **Коллектор → live-параметры** (`LIVE_PARAM_COLLECTORS`, см. `etl/applier.py`): свёртка «сто
   датчиков» в скаляры-агрегаты (`maxLevelDb`, `countExceed24h`, `avgLevelDb`) — один вход в поток
   (кванторы → агрегат, см. учебник Часть 3).
4. **Регламенты домена ШУМ-ИИ**: например, «шум у школы ночью > 45 дБ → наряд/уведомление»
   (СанПиН 1.2.3685-21), «сейсмо-всплеск у трассы → проверка». Критерий решённости —
   `sensor_returned_normal`.
5. **Вкладка в Ситуационном центре** «📢 Шум/сейсмика (ШУМ-ИИ)» — карта датчиков, светофор
   приёма (`noise_health`), таймлайн событий (по образцу вкладки DAS-оптоволокна).
6. **Архитектурная заметка (НИР-2024 §2.4):** датчики дают тысячи сигналов/с — **агрегация на
   местах**, в РАГРАФ приходят только события, требующие реакции. Сырьё/видео хранится локально;
   к нам — дескрипторы. При перемещении датчика — новый `sensor_id`, старый архивируется.

## 3. Проверка (curl)

```bash
# сырой 3-осевой сэмпл
curl -X POST localhost:8000/api/ingest/noise -H 'Content-Type: application/json' \
  -d '{"sensor_id":"shum-vki-01","x":8736,"y":2342,"z":0,"ts":1728961597128,"pos":"44.34532N 72.4534543E"}'
# пачка высокоуровневых событий
curl -X POST localhost:8000/api/ingest/noise -H 'Content-Type: application/json' \
  -d '{"events":[{"sensor_id":"shum-vki-01","event_type":"train","level_db":78.4,"ts":1728961597344,"coords":"44.34532N 72.4534543E"}]}'
curl localhost:8000/api/ingest/noise/stats
curl localhost:8000/api/ingest/noise/health
```
