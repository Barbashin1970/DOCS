# SKILL: Modern Frontend UI/UX for NSU AI Center Task Tracker

## 1. Контекст проекта (Project Context)
Вы — Senior Frontend Engineer & UX/UI Designer. Ваша задача — разработать высокопроизводительный, современный и интуитивно понятный интерфейс таск-трекера для Центра ИИ НГУ. 
Интерфейс должен ощущаться быстрым как Linear и функциональным как ClickUp. Пользователи — менеджеры, аналитики и инженеры, работающие с сотнями задач, бюджетами и внешними партнерами (МТС, РТК, Альфа-Банк).

## 2. Технологический стек (Frontend Tech Stack)
Генерируйте код, строго используя следующий стек:
- **Framework:** React 18+ (или Next.js App Router).
- **Language:** TypeScript (строгая типизация всех API-ответов и пропсов).
- **Styling:** Tailwind CSS (с использованием `clsx` и `tailwind-merge` для динамических классов).
- **State Management & Data Fetching:** TanStack Query (React Query) для кеширования и синхронизации с бэкендом, Zustand — для локального UI-стейта.
- **Drag-and-Drop:** `@hello-pangea/dnd` (современный форк react-beautiful-dnd) или `dnd-kit`.
- **UI Components:** Radix UI / Shadcn UI (headless-компоненты для доступности и кастомизации).

## 3. Глобальный макет (App Layout)
Система должна иметь классический для enterprise-SaaS трехпанельный дизайн (Desktop-first):
1. **Сайдбар (Left Sidebar):** Навигация по Партнерам (Заказчикам) и вложенным в них Проектам. Возможность сворачивать сайдбар для расширения рабочей зоны.
2. **Топбар (Top Header):** Глобальный поиск (Command+K / Ctrl+K), хлебные крошки (Партнер -> Проект), фильтры (по исполнителю, тегам, дедлайну) и переключатель видов (Канбан / Список / Гант).
3. **Рабочая область (Main Canvas):** Зона рендеринга самой доски или списка задач.

## 4. Канбан-доска (The Kanban View)
- **Колонки:** Отражают статусы (Inbox, To Do, In Progress, Waiting, Review, Done). В заголовке колонки выводится счетчик задач.
- **Карточки задач (Task Cards):** Компактные, но информативные. 
  - *Обязательные элементы на карточке:* ID задачи, Название, Аватар исполнителя, Дедлайн (краснеет, если просрочен), цветные теги приоритетов (P1-P4, как в проекте Мэрии).
  - *Индикаторы:* Иконка с количеством комментариев (чат) и счетчик вложенных файлов.
- **Взаимодействие:** Плавный Drag-and-Drop. При перетаскивании должна применяться стратегия **Optimistic UI Update** (карточка визуально встает в новую колонку мгновенно, не дожидаясь ответа от сервера; если сервер вернул ошибку — откатывается назад).

## 5. Карточка задачи (The Task Modal / Side Peek)
Это "сердце" системы. При клике на задачу она должна открываться **не на новой странице**, а выезжать справа (Drawer/Side Peek) или открываться в широком Modal, чтобы пользователь не терял контекст доски.
Разделите карточку на две смысловые зоны (Left/Right Layout):

### Левая колонка (Контент и Метаданные)
- **Шапка:** ID задачи, кнопка "Копировать ссылку", меню действий (...).
- **Название и Описание:** Редактор с поддержкой Markdown (WYSIWYG), чек-листов (Acceptance Criteria) и вставки таблиц.
- **Блок атрибутов (Grid):** Исполнитель, Проект, Дедлайн, Оценка времени (Estimated), Бюджет. 
- *Наследие Мэрии:* Блок пользовательских тегов (Направления/KPI/Impact) с ярким цветовым кодированием (Tailwind colors: `bg-indigo-500`, `bg-amber-500` и т.д.).

### Правая колонка (Activity Feed & Чат — Наследие Мэрии)
Вся история и коммуникация происходят здесь в единой ленте:
- **Встроенный мессенджер:** Полноценный чат для обсуждения задачи (таблица `tscomments`). Поддержка упоминаний (`@username`), прикрепления файлов.
- **История статусов (Audit Trail):** В эту же ленту чата системными серыми сообщениями вплетаются логи перемещений (например, *"Алексей перевел задачу из In Progress в Waiting • 14:30"*). Это дает полный контекст того, что происходило с задачей и что обсуждали в этот момент.

## 6. UX Паттерны и Перформанс (Core Rules)
1. **Скелетоны (Skeleton Loaders):** Вместо крутящихся спиннеров (spinners) используйте серые пульсирующие блоки, повторяющие форму контента при загрузке доски.
2. **Focus & Keyboard:** Поддержка навигации с клавиатуры (стрелки для перемещения фокуса по карточкам, `Space` для назначения на себя, `Esc` для закрытия карточки).
3. **Empty States:** Красивые заглушки с иллюстрациями и кнопкой "Создать", если в колонке или проекте еще нет задач.
4. **Debounce:** При вводе текста в поиск или изменении ползунков (настроек) используйте debounce, чтобы не спамить API-запросами бэкенд на каждое нажатие клавиши.


## С этим ТЗ фронтенд-разработчик (или ИИ-ассистент) не сделает "очередную скучную админку", а построит современный интерфейс уровня лучших мировых продуктов. Чат внутри задачи, интегрированный с логом смены статусов (как вы это делали в проекте мэрии), — это киллер-фича, которая избавляет от необходимости постоянно переключаться в Telegram.
